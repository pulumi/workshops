## Story

1. **The moment.** In August 2025, Google Threat Intelligence Group reported that the actor UNC6395 used compromised OAuth tokens to export data from many Salesforce instances, then searched that data for secrets such as AWS access keys. The advisory recommends that organizations "revoke and rotate credentials for those applications". Source: https://cloud.google.com/blog/topics/threat-intelligence/data-theft-salesforce-instances-via-salesloft-drift (read 2026-10-11). The advisory does not say the tokens were never rotated, so the deck does not say it.
2. **The tension.** If you never rotate, a stolen copy keeps working. If you rotate by hand, one missed reader means an outage.
3. **Why it is hard.** A new secret value has many readers. Rotation has to change the value and keep every reader working while it changes.
4. **The questions.** Five: what happens to running apps while a secret changes; who runs the rotation; how the app gets the value without a stored key; what about credentials outside Secrets Manager such as an IAM key; how to stop a secret that never rotates from shipping.
5. **The answers.** Version labels (AWSCURRENT, AWSPREVIOUS, AWSPENDING) and the four-step rotation Lambda declared in Pulumi IaC; Pulumi ESC with OIDC login and the aws-secrets provider; the ESC aws-iam rotator; a Pulumi policy pack at preview.
6. **The proof.** The demo rotates a real secret, reads both versions through ESC, rotates an IAM user's keys, and fails a preview for a secret with no rotation.
