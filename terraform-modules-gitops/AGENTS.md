# AGENTS.md: terraform-modules-gitops

Guidance for coding agents (and humans) working in this workshop folder of `pulumi/workshops`.

## What this folder is

The material for the workshop "Keep your Terraform modules, change the pipeline: Terraform modules in Pulumi with push-to-deploy and drift detection" (90 minutes, AWS, TypeScript). Demo code in numbered folders that follow the demo flow, and later a Slidev deck. `README.md` has the layout and how to run each step.

The repo carries what an attendee or a future presenter needs: the demo code and these notes. The presenter's working documents (runbook, rehearsal checklist, fact-check log, open questions) stay on the presenter's machine; `.gitignore` keeps every `*.md` out except `README.md`, the `AGENTS.md` files and `slides/slides.md`. A new working document is ignored by default. That is deliberate; do not force-add it.

## Rules

- Stay inside this folder. Never modify other workshop folders in this repo.
- Facts about Pulumi products come from the docs listed under "Sources" in `README.md`. If a doc is unclear, write the question down instead of guessing.
- Canonical names: Pulumi Neo, Pulumi ESC, Pulumi Cloud, Pulumi IaC, Pulumi console (lowercase console). Never "Copilot", "Pulumi Service", "Insights", "CrossGuard".
- Conventional Commits, scoped to this folder, e.g. `feat(terraform-modules-gitops): ...`, `docs(terraform-modules-gitops): ...`.
- Do not commit credentials, `node_modules/`, `bin/`, `dist/`, generated `sdks/`, state or recordings.
- Every command shown on a slide or in the README is one the demo runs, with the same flags.

## Demo code

- Each of `01` to `06` is a complete project, the state of the participant repo `tf-modules-gitops` at the end of that step. `02` to `06` share one `package.json` and `package-lock.json`. When you change a dependency, change it in all of them.
- Versions are pinned (see the table in `README.md`). The `hcl` version in `Pulumi.yaml` is the one `pulumi package add` wrote, not a guess. Re-run the command and record what it writes before changing it.
- `sdks/` is generated by `pulumi install` from `Pulumi.yaml` and is ignored.
- `00-preflight/`, `07-drift/`, `08-teardown/`, `create-env.sh`: bash, shellcheck clean (`shellcheck -x $(find . -name '*.sh')`).
- Check per project: `pulumi install && npx tsc --noEmit`. Preview offline on a throwaway local stack with dummy credentials and `aws:skipCredentialsValidation`, `aws:skipMetadataApiCheck`, `aws:skipRequestingAccountId`, `aws:skipRegionValidation` set. Never commit those settings or that stack's config. `Pulumi.dev.yaml` with an `environment:` block cannot run on a local backend, because ESC needs Pulumi Cloud.
- `pulumi stack rm` deletes the stack's `Pulumi.<stack>.yaml`. Do not run it in a folder whose config file you need.
- `allowedCidr` in the committed `Pulumi.dev.yaml` is a documentation-range placeholder (203.0.113.10/32). Never commit a real IP.
